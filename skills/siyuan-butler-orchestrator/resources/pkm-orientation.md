# Butler PKM 定位

## 1. 这套 PKM 真正在追求什么

这套方法论的第一原则不是“写出好笔记”，而是“减少火花熄灭的概率”。

Butler 要服务的不是一个高维护的知识花园，而是一个低摩擦的火花保存系统。它优先保护的是：

- 心流不断
- 火花先被接住
- 未来仍有重返入口
- 写入始终在清晰边界内发生

## 2. 三层结构

### 2.1 捕获层

- 任务：先接住火花，防止蒸发
- 允许：短句、词组、截图、链接、时间戳、对话片段、问题、意象词
- 不要求：完整、规范、立刻可检索

### 2.2 日记层

- daily note 不是第一入口，而是汇流层
- 它负责把当天少数真正值得保留的 Sparkle 收进时间轴
- 它回答的不是“今天发生了什么”，而是“今天有什么值得以后再碰一次”

### 2.3 沉淀层

- 只有反复出现、逐渐长出形状的主题，才值得沉淀成独立页面或连接网络
- 沉淀不是每条记录的默认终点

顺序必须是：先捕获，再汇流，最后沉淀。

## 3. Sparkle 的核心定义

- Sparkle 不是完整笔记，也不是文本摘要
- Sparkle 是最小可回忆单元
- Sparkle 的任务不是准确复述，而是让未来的自己重新回到刚才那个状态

一句最凝练的定义：Sparkle 是一个“重返入口”。

## 4. Sparkle 的最小结构

一个 Sparkle 至少要保住两件事：

- `source`：它从哪里亮起来
- `glow`：这里真正发亮的是什么

可选增强：

- `trace`：辅助线索
- `pull`：后续牵引方向

## 5. Orchestrator 需要一直记住的边界

- 不把所有值得讨论的内容都推进为记录
- 不把 daily note 当成第一触点
- 不把双链当成输入义务
- 不让 Capture 或 Rekindle 绕过 review
- 不把 Butler 说成通用 CRUD 工具

## 6. V0 只覆盖到哪里

当前 V0 的主链路只收拢三件事：

- 接住 Sparkle
- 让既有 Sparkle 复燃成正式条目提案
- 在 review 边界内决定是否写入

沉淀层和长期主题页仍是后续方向，不应提前塞进当前 workflow。
