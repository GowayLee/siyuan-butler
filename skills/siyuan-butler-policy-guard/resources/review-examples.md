# Review 例子

## 1. 可直接 `allow` 的例子

场景：

- 用户明确说“先帮我记一下”
- 动作是把一条 Sparkle append 到 `sparkles`
- 目标日期明确
- 没有额外联动

审查倾向：

- 可以 `allow`

## 2. 应 `ask_confirm` 的例子

场景：

- 这次要把内容写成正式正文
- 或者这次动作会明显扩大用户可见写入范围

审查倾向：

- 用户应先看到写到哪里、写什么、会附带什么影响
- 因此更适合 `ask_confirm`

## 3. 应 `downgrade` 的例子

场景：

- 正文提案还很空
- 目标日期不明确
- 写入预览还没成形

审查倾向：

- 先不落盘
- 保留在 proposal 层或 draft 层

## 4. 不该靠 Guard 兜底的例子

场景：

- 用户明确说暂时不记
- 根本没有锁定要写到哪里
- 当前内容只是闲聊噪声

处理倾向：

- 更适合由 Orchestrator / Capture / Rekindle 在更上游就拦住
- 不要把所有“不该继续”的情况都拖到 Guard 阶段
