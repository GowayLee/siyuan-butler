# Review 边界

## 1. Guard 守的是什么

Guard 守的是 `propose -> review -> write` 里的 review 边界。

它不负责创作 Sparkle 或正文，也不负责决定对话本身有没有笔记价值。它负责把已经收拢好的写入意图关进清晰、可预览、可解释的边界里。

## 2. Review 前提

进入 Guard 前，输入对象应当已经是 `WritePlan`，而不是一段自由文本，也不是半成品语义判断。

## 3. Guard 最关心的四件事

- 目标是否明确
- 预览是否清晰
- 语义是否匹配
- 副作用是否可接受

## 4. 哪些情况更应谨慎

- 正式条目写入
- 状态回写
- 关联回写
- 多块联动写入

## 5. 哪些情况相对更轻

- 低风险的 `append-sparkle`
- 目标明确
- 预览清晰
- 没有额外副作用

## 6. 当前 V0 的真实语气

Guard 不是为了制造阻力，而是为了防止写入边界在对话里被悄悄扩大。
