# Capture 模式与例子

## 1. 四种最小成立形式

### 1.1 一句意象

适合音乐、摄影、情绪、审美。

例：

- `source`: Debussy《Voiles》
- `glow`: 帆 / 雾 / 不显形的方向

### 1.2 一条判断

适合技术、产品、方法论。

例：

- `source`: 和 AI 聊 ampcode
- `glow`: 引用关系真正服务的是 handoff 连续性

### 1.3 一个触发 + 一个延伸

适合阅读、网页、播客、谈话启发。

例：

- `source`: 看一篇 NixOS 博客
- `glow`: declarative system 的价值是长期迁移，不只是复现

### 1.4 一个待展开问题

适合知道它重要，但现在不想展开。

例：

- `source`: 听象征主义音乐时
- `glow`: 为什么它总像在制造对象的轮廓，而不是对象本身？

## 2. 常见场景提示

- 音乐欣赏：曲目 + 时间点 + 意象词
- 摄影与后期：图片 / 局部观察 + 空气感 / 空间关系
- 阅读网页：链接 / 标题 + 改写后的理解
- 和 AI 讨论：对话主题 + 核心判断
- 科研与实验：实验观察 + 方法判断 / 下一步方向

## 3. Capture 时不要做的变形

- 不把意象翻译成说明文
- 不把判断扩写成正式论述
- 不强求 trace / pull / tags 都齐全
- 不把双链规划当作输入义务

## 4. 人称与口吻例子

应优先写成贴近用户落笔的一人称，而不是 Butler 站在旁边转述。

反例：

- `glow`: 用户意识到 declarative system 真正值钱的是长期迁移能力，不只是复现
- `glow`: 这段对话表达了他对方向感而非对象本身的偏好

正例：

- `glow`: 我开始意识到 declarative system 真正值钱的是长期迁移能力，不只是复现
- `glow`: 我喜欢的不是对象本身，而是它将要显形时那种方向感
